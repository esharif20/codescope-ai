<objective>
Extract raw call-expression and class-base data from a single Python source file (CS-021, call half). Two
sibling extractions, one module: (1) every call expression found inside a function/method/nested-function body,
tagged with its receiver shape; (2) every class's raw, as-written list of base-class expressions. Neither
extraction resolves anything -- that is Plan 06's job, which depends on this plan's output plus Plan 05's import
resolution.

Purpose: Phase 1's symbols have no concept of calls or base classes. D-01 (inheritance-aware self/cls
resolution) cannot be built without a raw base-class list; D-02/D-03/D-04 (call resolution) cannot be built
without a raw call list that already distinguishes receiver shape (bare name vs self/cls vs other attribute).
Output: `backend/app/analysis/calls.py` with `extract_raw_calls` and `extract_raw_class_bases`.
</objective>

A call `foo()` -> `call` node, field `function` (an `identifier` for a bare name, or an `attribute` node for
`x.y()`/`a.b.c()`), field `arguments` (`argument_list`, ignore its contents -- this phase never inspects call
arguments). An `attribute` node has field `object` (the receiver expression -- an `identifier` for `self.x()`
or `obj.x()`, itself another `attribute` for `a.b.c()`) and field `attribute` (an `identifier` -- the final
name, e.g. `"baz"` in `obj.baz`).

A class's bases: `class_definition` node, field `superclasses` -> an `argument_list` node whose named children
(skip the literal `(`, `)`, `,` tokens) are the raw base expressions in left-to-right source order (each is
either an `identifier`, e.g. `Base1`, or an `attribute`, e.g. `mod.Base2` -- use its full source text either
way). A class with no parens at all (`class C:`) has no `superclasses` field (`child_by_field_name
("superclasses")` returns `None`) -- treat that as zero bases, not an error.

Scope/enclosing-symbol tracking: reuse the exact same scope-stack mechanics as `_walk_symbols` in
`python_symbols.py` (`_Frame = tuple[str, bool]`, `scope: tuple[_Frame, ...]`) so `enclosing_symbol` values are
byte-for-byte the same qualified names Phase 1 already produces for the containing function/method (do not
reinvent qualified-name logic -- import and call `_qualified_name`/`_parent_qualified_name`-equivalent logic by
either importing the private helpers from `python_symbols` directly, or re-walking with the identical frame
convention; prefer importing `app.analysis.python_symbols._qualified_name` since the module is internal to this
package and the function is already exactly what is needed).

from typing import Literal

from pydantic import BaseModel


class RawCall(BaseModel):
    enclosing_symbol: str  # qualified_name of the containing function/method; NOT module_path-prefixed yet

Scope boundary (explicit, do not exceed): only extract calls found lexically inside a function, method, or
nested-function BODY (i.e., only while the scope stack is non-empty and its innermost frame is a
function-shaped frame, matching how `_walk_symbols` descends into a `function_definition`'s `body` field).
Calls at pure module level, inside a class body but outside any method, inside decorator expressions, or inside
parameter default-value expressions are explicitly OUT OF SCOPE for this phase (Phase 3 owns route-decorator
parsing) -- do not extract them, and do not record them as unresolved either.

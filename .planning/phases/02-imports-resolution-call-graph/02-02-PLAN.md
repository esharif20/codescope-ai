Design note on construction calls: a bare call to a name that resolves (via import or local lookup) to a CLASS
symbol -- e.g. `AuthService()` -- IS a resolved edge to that class's node. This is purely syntactic (name ->
import binding -> target symbol), not instance/variable tracking, so it stays within D-04's "strictly
syntactic" boundary. D-04's own example (`svc = UserService(); svc.login()`) is about what happens AFTER
construction (a method call on a local variable) -- that stays unresolved. Both patterns appear side by side
below.

Expected RESOLVED call edges (caller -> callee, both in `module_path:qualified_name` form) once Phase 2's
resolver runs against this fixture:

1. `services.auth:AuthService.login` -> `services.base:BaseService.audit` (inherited self-call, D-01)
2. `services.auth:AuthService.login` -> `services.auth:AuthService.check_password` (own-class self-call, D-01)
3. `routes.users:get_user` -> `services.auth:get_current_user` (bare imported function call)
4. `routes.users:get_user` -> `services.auth:AuthService` (bare call to an imported CLASS name -- construction)
5. `routes.users:update_user` -> `services.auth:get_current_user` (second, distinct caller of the same callee)
6. `routes.users:update_user` -> `callers:dispatch` (bare imported function call, cross-package)
7. `callers:call_get_user_directly` -> `routes.users:get_user` (bare imported function call)
8. `callers:warm_cache` -> `services.auth:get_current_user` (third distinct caller of the same callee)
9. `callers:call_twice` -> `services.auth:get_current_user` (ONE edge, TWO call-site lines -- D-10 dedup case)
10. `tests.test_services:test_login_succeeds` -> `services.auth:AuthService` (bare call to imported CLASS name)

Expected UNRESOLVED call sites (enclosing_symbol, expression):

1. `services.base:BaseService.audit` -> `print` (builtin bare call)
2. `routes.users:get_user` -> `auth.login` (method call on untyped local variable, D-04/D-14)
3. `callers:dispatch` -> `handler` (getattr-based dynamic dispatch, D-14)
4. `callers:run_task` -> `callback` (call on a function parameter, D-14)
5. `callers:process` -> `handler.process_item` (attribute call on unannotated parameter, D-02/D-14)
6. `tests.test_services:test_login_succeeds` -> `svc.login` (method call on untyped local variable)
